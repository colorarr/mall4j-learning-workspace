# 部署总览

Mall4j 当前后端部署只有一个 Java 服务：

| 服务 | 说明 | 默认端口 |
| --- | --- | --- |
| `yami-shop-admin` | 单体接口，管理端和用户端 API 都由它提供。 | `8080` |

依赖服务：

```text
MySQL
Redis
```

可选服务：

```text
XXL-JOB
Nginx
对象存储或本地文件存储
```

## 推荐部署顺序

1. 准备 MySQL，导入 `db/yami_shop.sql`。
2. 准备 Redis。
3. 打包后端。
4. 部署 `yami-shop-admin`。
5. 打包并部署前端。
6. 配置 Nginx 域名和反向代理。
7. 配置文件上传、支付回调、静态资源域名。

## 后端打包

在仓库根目录执行：

```powershell
mvn clean package -DskipTests
```

生成的 jar 默认位于：

```text
yami-shop-admin/target/yami-shop-admin-0.0.1-SNAPSHOT.jar
```

## 前端打包

管理后台：

```powershell
cd ..\front-end\mall4v
pnpm i
pnpm run build
```

构建输出目录以 Vite 配置为准。

## 完成后应该看到

- 单体后端 jar 已生成。
- 生产配置中的 MySQL、Redis 地址已改成真实环境。
- 管理后台静态文件已构建完成。
- Nginx 能访问前端页面并转发接口。
- 管理后台能成功登录。

## 检查题-含答案

问题：为什么只部署 `yami-shop-admin`？

答案：`yami-shop-admin` 已依赖 `yami-shop-api`，管理端和用户端 API 会一起打包并监听 `8080`。

问题：生产端口为什么不能只看 README 的本地端口？

答案：当前 `dev/docker/prod` 都按单体端口 `8080` 配置，上线仍要确认 Nginx 和前端地址一致。
